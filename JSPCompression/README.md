这是一个对单个JSP文件里的所有标签压缩成一行的项目,它的目标结果,正如你在部分浏览器的"查看网页源代码"里看到的"意大利面"一样的HTML源代码一样。

该压缩的目的是将结果交由Eclipse IDE进一步格式化,因为其"尊重"部分EL表达式里的不必要的(个人认为的)回车换行。

我们假定场景在CRLF(回车换行)下,LF(回车)场景今后会兼容(也许吧)。

在此之前,请区分两种回车换行,第一种是转义字符的回车换行(在字符串里手写\r\n),第二种是源代码字符。想象你在一个IDE里编码,你想在控制台输出一个回车换行,你会在字符串里手动输入\r\n,这是转义字符;你在一个分号后回车,表征前面的一条语句的求值和副作用必须早于分号后的语句,这个回车换行是源代码字符。我们做的是源代码字符层级的修改,也即去遍历*.JSP文件里的每个字符,当你遇到转义字符,我们的项目会认为:"'\',这是一个字符;'r',这是一个字符;'\',这是一个字符;'n',这又是一个字符。"而项目看到源代码字符的回车换行时,它会看到:"ASCII 0x0D,这是一个字符;ASCII 0x0A,这又是一个字符。"转义字符只有在编译时才会转化成控制台输出的回车换行,而源代码字符的回车换行在编译时根本对结果无影响(因为编译器也许并不依赖其,如JAVA和C/C++项目)。

源代码字符的回车换行是让JSP文件看起来不像"意大利面"的罪魁祸首,尽管看起来像"意大利面"也许比普通非格式化排版更有罪,但这是我们现在的目的:压缩源代码字符的回车换行,让JSP文件只有一行。

由于JSP文件里有实践或语法依赖于源代码字符,做出如下主观约定,团队在JSP编码时,不能在JSP文件里出现如下情况,否则压缩会出现语义损失:

1.不在<pre>和<textarea>内硬编码依赖换行的纯文本

2.不含text/plain这类可能的csv输出

3.JS块里不用反引号定义YAML,也不在前端输出JS定义的反引号里的内容

4.不用三个双引号表征的文本块

5.不通过渲染器展示自定义标签

6.不把自定义标签体的内容传给后端

7.JS里不使用分号自动插入

8.不使用CDATA

9.正则表达式不写未转义的空格

10.无引号的HTML标签属性中空白字符不连续出现

理由如下:

1、2、3、5为渲染问题,由于CRLF可能会被渲染到前端,造成语义丢失,观看者无法理解,尽管这和程序可运行性没有任何关系

3中的YAML依赖于换行和缩进管理内容,故排除,如有必要会在反引号内使用不换行的标准JSON

4中的文本块的内容依赖于换行

6中,可维护性极差的后端可能会使用换行字符来对标签体内容解析,如果压缩会造成后端无法识别

7中,对于returnCRLF{...}的内容,它的语义为return;{...},它返回undefined;如果将它变成return%ASCII:0x20,这是空格%{...}后,它返回{...},源代码字符级别的回车会造成语义改变,故不用。此外,JS块里还有break、continue、throw关键字会出现上面的相同场景。

8中,CDATA文本数据不由XML解析器进行解析,所以依赖于源代码字符级别的回车换行,故不用

9中,正则可以依赖空格,这里直接排除未转义空格使用

10中,连续出现的空白字符,被我认为是不好的排版,故排除

上面的规则持续维护更新中。

对原文本压缩,我们采用状态机的方式,不使用正则表达式和抽象语法树(AST),这是因为:我在GitHub查看了一个名为JSPCompression的开源项目,阅读其依赖于正则表达式的源码,发现有许多条件下压缩会造成语义损失。AST编码难度则过高,不适于简单脚本。

定义状态机如下:

1.遍历源代码文本,在引号外,遇到任何空白字符(空格、Tab制表符、CR、LF),统一替换成一个普通空格。它们的具体情况分别是:

CR:0x0D,转义为\r

LF:0x0A,转义为\n

Space:0x20,转义就是其本身

Tab:0x09,转义为\t

2.字符串字面量保护模式,所有引号内的字符原样输出,当且仅当遇到字符反斜杠时,索引+2,继续移动和扫描引号,并输出(这条规则为了正确识别\"这类字符,防止意外截断)。注意,区分引号类型,单引号和双引号不能混用。

3.遇到所有注释,丢弃之。注释情况如下:

HTML注释<!-- -->

JSP注释<%-- --%>

JS单行注释//

JS多行注释/**/

exe文件使用g++进行release编译。运行格式:JSPCompression.cpp input.jsp output.jsp
